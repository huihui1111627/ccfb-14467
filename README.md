# 多射频无线网状网信道分配与链路调度规划器

针对山区景区无线覆盖:山上拉不了光纤,杆子之间靠无线 mesh 多跳回传到有线出口。
本工具联合优化 **路由 × 信道分配 × 时隙调度**,并用按 SINR 逐时隙判定成败的
仿真验收,输出每个杆子到出口的端到端吞吐/时延。

## 运行

```bash
python3 run_demo.py      # 主场景规划 + 基线对比 + 小规模穷举对比,生成 report.html
python3 test_meshnet.py  # 自洽性测试
open report.html         # 地形图(链路按信道上色)、时隙表、指标对比
```

## 设计要点(对应需求)

1. **冲突图与累加干扰** — `planner.build_conflict_graph` 建两两冲突边用于分析;
   调度判定不只看两两:`_slot_feasible` 对候选时隙内所有发射做**累加干扰**
   的 SINR 检验(物理干扰模型),好几条远处链路同时发的干扰会加起来。
2. **射频约束** — 每杆射频数固定(`Node.radios`),`assign_channels` 在射频粒度
   分配信道,链路两端必须共信道才通;断链修复用最小破坏贪心,保证不拆断网络。
3. **部分重叠信道** — `model.overlap_factor`:2.4G 按 22MHz 占用线性折算,
   只有 1/6/11 完全不重叠;干扰按重叠比例打进 SINR。
4. **时隙调度** — 32 时隙一个周期;链路所需时隙数 ∝ 负载/速率;每个时隙选一组
   累加 SINR 可行的链路同发;先给每条承载链路保底 1 槽,再加权轮转填充。
5. **联合优化** — `plan_network` 迭代:路由(容量感知代价)→ 信道 → 调度 →
   用调度出的容量更新路由代价,闭环数轮,以"最差杆的 max-min 公平吞吐"为
   目标取最优,而不是先定路由再配信道。
6. **顺流时隙** — 调度按"离出口远的链路优先、每条链路抢最早可行槽"排序,
   包在一个周期内逐级汇入,避免每跳等一整周期(仿真里逐跳按时隙位置算时延)。
7. **DFS 雷达** — `plan_dfs_backup` 给每条 DFS 链路预选备用信道,选择标准是在
   该链路已分配的时隙里**预演切换后的累加 SINR**,保证雷达来时立即切换、
   业务不断(仿真注入雷达事件验证:断链时隙 0)。

## 验收口径

`simulate.py` 与规划器相互独立:逐时隙、逐接收机按累加干扰重新判定 SINR
成败,吞吐按 max-min 公平分摊到各条流量,时延按调度表逐跳等槽累加。
对比方案:全网同一信道、按经验隔跳换信道(1/6/11 轮换)、小规模穷举最优
(枚举全部射频信道组合,同一调度器与路由下取最差杆吞吐最大者)。

## 文件

| 文件 | 内容 |
|---|---|
| `meshnet/model.py` | 地形(高程栅格+通视/遮挡损耗)、信道重叠模型、SINR/速率 |
| `meshnet/planner.py` | 联合优化:路由、信道分配、时隙调度、DFS 备用 |
| `meshnet/simulate.py` | 验收仿真:逐时隙 SINR 判定,端到端吞吐/时延 |
| `meshnet/baselines.py` | 单信道 / 隔跳换信道 / 穷举最优 |
| `meshnet/report.py` | HTML 报告(地形图、链路信道着色、时隙表) |
| `run_demo.py` | 场景生成与全流程演示 |
